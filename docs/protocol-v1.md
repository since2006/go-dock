# go-dock 设备通信协议 v1

本文档描述 go-dock 主机程序（`host/`）与微雪 ESP32-S3-Touch-AMOLED-2.41-B 固件（`firmware/`）之间的 USB 串口协议。两端实现必须与本文档保持一致；改动协议时，需同时修改本文档和 `host/internal/device/protocol.go`。

## 1. 物理层

| 项目 | 约定 |
|---|---|
| 接口 | 板载 USB-C，直连 ESP32-S3 原生 USB（GPIO19/20），无 USB-UART 桥接芯片 |
| USB ID | 默认 USB-Serial/JTAG：`303A:1001`；若固件改用 TinyUSB CDC，ESP-IDF 默认 `303A:4001`。主机会把所有 VID 为 `303A` 的串口视为候选，并优先选择 PID `1001`/`4001` |
| 端口名 | macOS `/dev/cu.usbmodem*`（主机只打开 `cu.*`，不打开 `tty.*`）；Linux `/dev/ttyACM*`；Windows `COMx` |
| 波特率 | 原生 USB 无意义，主机固定传 115200 |
| 控制线 | 主机打开端口时 **DTR=1、RTS=0**。在 USB-Serial/JTAG 上翻转 RTS 可能触发芯片复位；TinyUSB CDC 通常把 DTR 当作「主机已连接」 |
| 编码 | UTF-8 |

**固件日志**：ESP-IDF/Arduino 的控制台日志和 ROM 启动信息默认也走这个端口。建议把控制台改到 UART0 或关闭（`CONFIG_ESP_CONSOLE_NONE` / 关闭 USB CDC On Boot 的日志），需要上报的日志改用下文的 `log` 消息。主机会忽略所有不是协议消息的行（只记 debug 日志），所以残留的启动输出不会破坏通信，但会浪费带宽。

## 2. 帧格式

- 每条消息是**一行 JSON 对象**，以 `\n` 结尾（设备发送 `\r\n` 也可以）。
- 一行（含结尾换行）**不超过 4096 字节**。超长的行，接收方整行丢弃。主机保证不超：`snapshot` 先从最不紧急的会话开始删 `agents[]` 条目（`agents_total` 和 `agents_active` 保留），还超再从末尾删会话；`pages` 从最后一页开始删控件，删空了再删页。
- 每个对象都有字符串字段 `t` 表示消息类型。
- 字符串不做 HTML 转义（`<`、`>`、`&` 原样发送）；非 ASCII 字符直接以 UTF-8 发送，不转成 `\uXXXX`。
- 时间一律为 **Unix 秒**（整数）。值为 `0` 表示「未知」。
- 接收方必须**忽略不认识的字段**和不认识的 `t`，以便向后兼容。

## 3. 主机 → 设备

### 3.1 `hello`

主机打开串口后立即发送；在收到设备 `hello` 之前，每 5 秒重发一次。

```json
{"t":"hello","proto":1,"host":"go-dock","ver":"0.1.0"}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `proto` | int | 协议主版本，本文档为 `1` |
| `host` | string | 固定为 `go-dock` |
| `ver` | string | 主机程序版本 |

设备收到后应回复自己的 `hello`（见 4.1）。

### 3.2 `snapshot`

完整的显示状态。设备收到后**整体替换**当前状态，不需要做增量合并。

发送时机：
- 打开串口后立即发送一次（不等设备握手，最简固件可以只解析 `snapshot`）
- 收到设备 `hello` 后立即发送一次
- 状态变化时发送（200 ms 防抖）
- 心跳：每 5 秒发送一次，即使没有变化

```json
{
  "t": "snapshot",
  "seq": 128,
  "now": 1792202470,
  "tz": 28800,
  "usage": {
    "claude": {
      "five_hour": {"pct": 62.0, "resets_at": 1792209670, "window_min": 300},
      "seven_day": {"pct": 31.0, "resets_at": 1792600000, "window_min": 10080},
      "today_tokens": 1834567,
      "today_cost": 12.84,
      "updated_at": 1792202400
    },
    "codex": {
      "five_hour": {"pct": 28.0, "resets_at": 1792210000, "window_min": 300},
      "seven_day": null,
      "today_tokens": 402113,
      "updated_at": 1792202300
    }
  },
  "sessions": [
    {"id": "claude:0f4f5b10-…", "p": "claude", "project": "go-dock", "state": "approval", "label": "需授权", "text": "Explore · Bash: cat ~/.ssh/config", "since": 1792202428,
     "agents": [
       {"type": "Explore", "text": "查看 ssh 配置与密钥代码", "state": "approval", "since": 1792202428},
       {"type": "Explore", "text": "查看工具栏与存储", "state": "running", "since": 1792202410}
     ],
     "agents_total": 3, "agents_active": 2},
    {"id": "codex:0199a1…", "p": "codex", "project": "api-svc", "state": "running", "label": "进行中", "text": "重构登录模块", "since": 1792202278},
    {"id": "claude:4a51cb15-…", "p": "claude", "project": "blog", "state": "done", "label": "已完成", "text": "Write the release notes", "since": 1792202350}
  ],
  "counts": {"approval": 1, "input": 0, "running": 1, "done": 1, "error": 0, "idle": 2},
  "total": 3
}
```

**顶层字段**

| 字段 | 类型 | 说明 |
|---|---|---|
| `seq` | uint | 递增序号，每发一次 `snapshot` 加 1；主机重启或重连后可能从小的值重新开始 |
| `now` | int | 主机当前时间。设备不需要 RTC，倒计时和经过时长都基于它计算（见 7.2） |
| `tz` | int | 主机所在时区相对 UTC 的偏移（秒，东八区为 `28800`），设备显示本地时钟用。旧版主机没有这个字段，按 `0` 处理 |
| `usage` | object | 固定包含 `claude` 和 `codex` 两个键，结构见下表 |
| `sessions` | array | 任务列表，**已按显示顺序排好**，设备不要重新排序 |
| `counts` | object | 各状态的会话数，包含被过滤掉的 `idle` |
| `total` | int | 应显示的任务总数（已排除 `idle`）。`sessions` 可能因数量上限或 4 KB 限制比它短，设备可显示「+N」 |

**`usage.claude` / `usage.codex`**

| 字段 | 类型 | 说明 |
|---|---|---|
| `five_hour` | object \| null | 5 小时额度窗口；未知时为 `null` |
| `seven_day` | object \| null | 7 天额度窗口；未知时为 `null` |
| `five_hour.pct` / `seven_day.pct` | number | 已用百分比 0–100，可能有小数 |
| `*.resets_at` | int | 重置时间；`0` 表示未知。重置时间已过时，主机会发 `pct: 0, resets_at: 0` |
| `*.window_min` | int | 窗口长度（分钟），通常为 300 / 10080；`0` 表示未知。标签可据此显示「5h」「7d」 |
| `today_tokens` | int | 今日（主机本地时区）token 数 = 输入 + 缓存写入 + 输出，**不含缓存读取**（每轮重复读取同一段上下文，会占到总数的 99%） |
| `today_cost` | number | 今日按 API 价格估算的费用（美元）。**仅 Claude 有**，无法估算时省略该字段 |
| `updated_at` | int | 额度数据的更新时间；`0` 表示从未获取。可据此提示数据陈旧 |

**`sessions[]`**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 稳定的会话 ID（`provider:session_id`），可用于翻页后保持选中项 |
| `p` | string | `claude` 或 `codex` |
| `project` | string | 工作目录名，最多 24 个字符（按 Unicode 字符计） |
| `state` | string | `approval` / `input` / `error` / `running` / `done` / `idle` |
| `label` | string | 状态的中文标签，设备可直接显示 |
| `text` | string | 一行摘要：当前动作（如 `Bash: npm install`），没有时为任务标题；最多 48 个字符，可能为空。只能显示一行的旧固件用它 |
| `since` | int | 进入当前状态的时间 |
| `title` | string | **可选**。会话名：用 `/rename` 改过时为改的名字，否则为自动生成的标题（Claude Code、Codex 都会在第一次提问后生成）；Codex 还没有标题时为第一次提问。最多 32 个字符。和 `detail` 相同或没有时省略 |
| `msg` | string | **可选**。AI 本轮最新一段回复的第一行（和 Claude Code 界面里 ● 开头的那句一样），去掉 Markdown 标记，按一行屏幕宽度截断（见下）。新一轮提问时清空；没有时省略。行太长时最先被去掉（在子代理之后、会话之前） |
| `detail` | string | **可选**。会话**自己**当前的动作，按一行屏幕宽度截断（见下）。运行中的命令显示 Claude 为它写的说明（如 `Check hooks install`，和 Claude Code 界面里命令上方那行一样），没有说明时显示 `工具: 参数`；Codex 的命令没有说明，显示 `Bash: 命令`，改文件显示 `apply_patch: 文件名`；等授权时总是显示实际命令（如 `Bash: rm -rf dist`）。Codex 调用 `request_user_input` 提问时状态为 `input`，`detail` 为「等待回答问题」（和 Claude Code 的 AskUserQuestion 一样）。会话自己这一轮已结束、但还有子代理在跑时，为「等待 N 个子任务完成」 |
| `turn_output` | int | **可选**。本轮（从用户这次提问开始）AI 输出的 token 数，和 Claude Code 转圈提示里的 `↓ 6.5k tokens` 一样；新一轮从 0 开始，为 `0` 时省略 |
| `turn_secs` | int | **可选**。截至 `now`，本轮 AI 已工作的秒数，和 Claude Code 转圈提示里的时间一样：**不含等用户授权、回答的时间**。会话（含子代理）从空闲变忙或用户提问时开始一轮，变回空闲时结束；后台子代理还在跑时继续计时。为 `0` 时省略 |
| `agents` | array | **可选**。会话的子代理（Claude Code 的 Agent 工具、Codex 派生的子线程），最紧急的在前，最多 3 个。没有子代理时省略 |
| `agents_total` | int | **可选**。子代理总数（含未列出和刚完成的）。没有子代理时省略，按 `0` 处理 |
| `agents_active` | int | **可选**。其中仍在工作或等待用户的个数。为 `0` 时省略 |

`msg` 和 `detail` 各占满一整行，按显示宽度截断：中文、日文、韩文、全角符号和 emoji 算 2 列，其他字符算 1 列，最多 64 列（约 30 个汉字或 60 多个英文字符），同时不超过 148 字节（固件缓冲区 152 字节，避免截断半个字符）；截断时以「…」结尾。

`state`、`label`、`text`、`since` 描述的是**会话本身和它的子代理中最紧急的那个**：子代理在等授权时，整行就是 `approval`，`text` 写成「`<子代理类型> · <它在做的事>`」，`since` 是该子代理的开始时间。会话本身这一轮已结束（`done` / `idle`，比如 Claude Code 派出后台子代理后就停下等结果）、但子代理还在跑时，整行是 `running`，`detail` 是「等待 N 个子任务完成」。

**`agents[]`**

| 字段 | 类型 | 说明 |
|---|---|---|
| `type` | string | 子代理类型，如 `Explore`、`general-purpose`、Codex 的角色名（没有角色时为它的昵称，如 `Kepler`）；最多 16 个字符 |
| `text` | string | 它被派去做的事（任务描述），没有时为它当前的动作；它在等授权、等输入或出错时，改为它要做的动作（如 `Bash: rm -rf dist`）。最多 32 个字符，可能为空 |
| `state` | string | `running` / `approval` / `input` / `error` / `done`（刚完成的会保留约 3 分钟） |
| `since` | int | 开始时间 |

**`state` 取值与显示顺序**（主机已按此排序；同一状态内最近更新的在前）

| state | label | 含义 | 建议颜色 |
|---|---|---|---|
| `approval` | 需授权 | 等待用户批准工具调用 | 琥珀色 `#FFB020` |
| `input` | 等待输入 | 等待用户回答问题、处理对话框 | 蓝色 `#3B9EFF` |
| `error` | 出错 | 本轮因错误结束（如限流） | 红色 `#FF5A5F` |
| `running` | 进行中 | 正在执行 | 绿色 `#3DDC84` |
| `done` | 已完成 | 本轮刚结束（默认保留 30 分钟） | 灰色 `#8A8F98` |
| `idle` | 空闲 | 会话开着但无事可做；默认不发送 | 深灰 |

### 3.3 `settings`（预留）

v1 主机不发送此消息，固件应忽略。后续用于亮度、自动熄屏等设置，例如：

```json
{"t":"settings","brightness":80,"sleep_after":600}
```

### 3.4 固件升级

主机把固件程序镜像（Release 里的 `go-dock-firmware-v2-app.bin`，不是从 `0x0` 开始刷的合并镜像）分块发给设备，设备写入空闲的 OTA 分区后重启进入新固件。只有设备 `hello` 带 `"ota":1` 时主机才会发起升级。

```json
{"t":"ota_begin","size":4013664,"ver":"0.1.4"}
{"t":"ota_data","off":0,"data":"6QYCT7RWN0Ds…"}
{"t":"ota_end"}
{"t":"ota_abort"}
```

| 消息 | 字段 | 说明 |
|---|---|---|
| `ota_begin` | `size`、`ver` | 开始一次升级：镜像字节数和镜像里的版本号。设备擦除目标分区（约 10 秒）后回复 `ready` |
| `ota_data` | `off`、`data` | 镜像从 `off` 开始的一段，`data` 为标准 base64，解码后最多 2048 字节。`off` 必须等于设备已写入的字节数 |
| `ota_end` | — | 镜像发完。设备校验镜像摘要、项目名（`go-dock-firmware`）和版本号，设为启动分区，回复 `done` 后约 1 秒重启 |
| `ota_abort` | — | 放弃本次升级，设备继续运行原固件 |

每条消息都要等设备回复（见 §4.5）后才发下一条，不能连发：设备 USB 接收缓冲有限（16 KB，早期固件 8 KB），满了会静默丢数据。主机的等待时间：`ready` 60 秒，`ack` 10 秒，`done` 30 秒；超时或收到 `error` 时发送 `ota_abort` 并报告失败。升级期间主机不发 `snapshot`。

设备 15 秒没收到下一块数据就自动放弃。新固件启动后处于试用状态：收到主机的 `hello` 或 `snapshot` 才确认保留；确认前重启，或 2 分钟内没联系上主机，bootloader 会回到原来的固件。主机在设备回复 `done` 后等待新版本的 `hello`：版本对上即成功；5 秒后仍报告旧版本，或 60 秒内没有报告，按失败处理（新固件已被回滚）。

### 3.5 `pages`

Agent 页右边的功能页，比如「灯光」。页面内容由主机上的插件生成（插件逻辑和 MQTT 等联网都在主机上），设备只按几种通用控件渲染，并把点击通过 `action`（§4.4）回传。只有设备 `hello` 带 `"pages":1` 时主机才发送；早期固件没有这个字段，只显示 Agent 页。网页的「设备预览」按同样的数据渲染（数据来自 `GET /api/device/pages`）。

```json
{"t":"pages","pages":[
  {"id":"lights","title":"灯光","summary":"1 / 2 盏亮着","items":[
    {"id":"main","kind":"switch","label":"办公室主灯","text":"已开","on":true},
    {"id":"desk","kind":"switch","label":"台灯","text":"切换中…","on":false,"busy":true}]}]}
```

设备收到后**整体替换**功能页列表；空列表 `"pages":[]` 表示只有 Agent 页。

发送时机：紧跟在每条 `snapshot` 后面。握手后、心跳时、固件升级没成功（设备没重启）后总是发送；状态变化时只在内容变了才发送。内容没变时设备可以不重绘。`snapshot` 和 `pages` 会连着到达（各最多 4096 字节），设备的 USB 接收缓冲应 ≥ 16 KB。

页面（最多 4 页，按顺序排在 Agent 页右边）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 页面 id：小写字母、数字、`-`、`_`，最长 16 字节。不截断，回传 `action` 时原样带上 |
| `title` | string | 页名，最多 8 个字，显示在顶栏 |
| `summary` | string | 可选。最多 24 个字，顶栏页名旁的摘要，如「1 / 3 盏亮着 · 1 盏未知」 |
| `error` | string | 可选。最多 24 个字，页面暂时不能用的原因，如「MQTT 未连接」。有它时用红色显示它，代替 `summary` |
| `items` | array | 控件，每页最多 6 个，按顺序排列 |

控件：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 同页面 id 的规则 |
| `kind` | string | 控件类型，见下表。不认识的类型画成不能点的卡片，只显示 `icon`、`label` 和 `text` |
| `label` | string | 名称，最多 12 个字 |
| `text` | string | 状态文字或数值，最多 8 个字，主机已写好：已开 / 已关 / 未知 / 切换中… / 26°C / 制冷 |
| `icon` | string | 可选。卡片上的图标，见 §7.1；没有或不认识时画灯泡。`stepper` 不画图标 |
| `on` | bool | 可选。开关状态；没有这个字段表示状态未知 |
| `busy` | bool | 可选。命令已发出，正在等设备回报 |
| `disabled` | bool | 可选。暂时不能操作（如 MQTT 未连接）：卡片置灰，不响应点击 |
| `at_min` / `at_max` | bool | 可选。`stepper` 的值已到下限 / 上限：对应的减 / 加按钮置灰 |

早期固件不认识 `stepper`、`select` 和 `icon`、`at_min`、`at_max`：这两种控件画成不能点的卡片，图标都画灯泡。

| `kind` | 控件 | 点击回传的 `act` |
|---|---|---|
| `switch` | 开关卡片（灯、空调电源） | 点卡片 `toggle` |
| `stepper` | 数值加减（温度），`text` 是数值 | 点「−」`dec`，点「+」`inc` |
| `select` | 选项轮换（模式、风速），`text` 是当前选项 | 点卡片 `next` |

字数按字符计，超出时主机截断并以「…」结尾；字段为假或为空时省略。

### 3.6 `beep`

让设备播放一段提示音。板子本身没有喇叭，要在排针上外接无源蜂鸣器（GPIO1，接法见 `firmware/README.md`「蜂鸣器提醒」）；没接时设备照常处理，只是不响。只有设备 `hello` 带 `"beep":1` 时主机才发送。

```json
{"t":"beep","notes":[[2637,160],[0,40],[2093,320]]}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `notes` | array | 依次播放的音符，每个是 `[频率 Hz, 时长 ms]`，频率 `0` 表示停顿。最多 16 个（多出的忽略）；频率 100–8000，超出范围按停顿处理；时长 10–1000 |

设备收到后立刻播放，打断正在播放的那段。音色都在主机上定义（`host/internal/device/beep.go`：叮咚、嘀嘀、上扬、急促，以及 8-bit 风格的拾取、升级、过关、跳跃、警笛），用户也可以在设置里自己写音符（`device.beep_custom`），加新音色不用升级固件。

发送时机：有会话或子代理**开始**等用户处理（`approval` 需授权、`input` 等待输入）时，紧跟在那条 `snapshot`（和 `pages`）后面发一次。同时开始等待的几个任务只响一次；一直等着不会重复响；设备重新插拔、重新握手后，不会为已经响过的任务再响；同一个会话被批准后又来一个授权请求，算新的一次。网页设置里点「试听」也会立即发送一条。用户可以在设置里关掉（`device.beep`）。

### 3.7 `ir_send`

让设备用外接的红外发射模块发一帧红外信号。编码全在主机上（目前是格力空调，`host/internal/ir`），设备只按时序发出，以后支持别的品牌不用升级固件。只有设备 `hello` 带 `"ir":1` 时主机才发送。

```json
{"t":"ir_send","hz":38000,"raw":[9000,4500,620,540,620,1600]}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `hz` | int | 载波频率，30000–60000，格力为 38000 |
| `raw` | array | 时长（µs），从 mark（载波开）开始，mark / space 交替；最多 512 个，每个 1–32767 |

设备收到后立刻发送，前一帧还没发完时排队（最多 4 帧，多出的丢弃），不回复。主机在空调插件的命令要发出时才发送；屏幕没连上或固件不支持时，命令直接报错，不会排队等到以后再发。

## 4. 设备 → 主机

### 4.1 `hello`

上电后发送一次；每次收到主机 `hello` 时也回复一次。

```json
{"t":"hello","proto":1,"fw":"0.1.0","w":600,"h":450,"max_line":4096}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `proto` | int | 固件实现的协议主版本 |
| `fw` | string | 固件版本 |
| `w` / `h` | int | 屏幕分辨率 |
| `max_line` | int | 设备能接收的最大行长度（含换行） |
| `ota` | int | **可选**。为 `1` 表示可以通过本连接升级固件（见 §3.4）；旧固件没有此字段 |
| `pages` | int | **可选**。为 `1` 表示能显示功能页（见 §3.5）；主机只给带此字段的设备发送 `pages` |
| `beep` | int | **可选**。为 `1` 表示能播放 `beep`（见 §3.6）；主机只给带此字段的设备发送。固件无法知道蜂鸣器有没有接上 |
| `ir` | int | **可选**。为 `1` 表示能发送 `ir_send`（见 §3.7），并会回报接收模块收到的信号（§4.6）。同样无法知道模块有没有接上 |

`proto` 与主机不一致时，主机在网页上报错，并**停止发送 `snapshot`**，但保持串口打开，仍可通过 §3.4 升级固件，升级后重新握手。

### 4.2 `ack`

可选。设备处理完一条 `snapshot` 后回复其 `seq`。主机只用它更新「最后响应时间」，不做重传。

```json
{"t":"ack","seq":128}
```

### 4.3 `log`

把固件日志转发到主机网页的「日志」页（带 `src=device` 标记）。

```json
{"t":"log","level":"info","msg":"battery 3.92V"}
```

`level` 取值为 `debug` / `info` / `warn` / `error`，无法识别时按 `info` 处理。

### 4.4 `action`

用户在功能页上点了一个控件。主机交给对应的插件处理，不回 `ack`；结果体现在之后的 `pages` 里：先是 `busy`，收到设备回报后更新 `on` 和 `text`（没回报时 5 秒后显示「未响应」）。

```json
{"t":"action","page":"lights","item":"main","act":"toggle"}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `page` | string | `pages` 里的页面 `id` |
| `item` | string | 控件 `id` |
| `act` | string | `switch` 支持 `toggle`（屏幕点击用这个）、`on`、`off`；`stepper` 支持 `inc`、`dec`；`select` 支持 `next` |

主机只处理握手完成且协议兼容时收到的 `action`，固件升级期间收到的直接丢弃。切换页面是设备本地的事，不用告诉主机。原先预留的 `touch` 消息不再使用。

### 4.5 `ota`

设备对 §3.4 各条消息的回复。

```json
{"t":"ota","state":"ready"}
{"t":"ota","state":"ack","off":2048}
{"t":"ota","state":"done"}
{"t":"ota","state":"error","msg":"写入失败（ESP_ERR_FLASH_OP_FAIL）"}
```

| `state` | 回复 | 说明 |
|---|---|---|
| `ready` | `ota_begin` | 分区已擦除，可以发送数据 |
| `ack` | `ota_data` | `off` 为已写入的总字节数 |
| `done` | `ota_end` | 镜像有效，已设为启动分区，即将重启 |
| `error` | 任一条 | `msg` 说明原因；设备已放弃本次升级 |

### 4.6 `ir_recv`

外接的红外接收模块收到一帧信号（比如有人用了空调的原装遥控器）。主机能解码时更新对应插件的状态（格力空调），否则只记 debug 日志。

```json
{"t":"ir_recv","raw":[9080,4440,680,480,680,1540]}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `raw` | array | 解调后的时长（µs），从 mark 开始，到最后一个 mark 为止；最多 512 个（当前固件最多 384 个），更长的帧截断 |

空闲超过 30 ms 算一帧结束：格力一帧中间有约 20 ms 的间隔，不能在那里切开。设备发送 `ir_send` 期间和发完后 50 ms 内收到的信号丢弃，免得把自己发的当成遥控器。主机只处理握手完成且协议兼容时收到的 `ir_recv`。

## 5. 时序

```
主机                                   设备
 │  打开串口（DTR=1, RTS=0）              │
 │──── hello ───────────────────────────▶│
 │──── snapshot(seq=1) ─────────────────▶│  渲染
 │◀─────────────────────────── hello ────│
 │──── snapshot(seq=2) ─────────────────▶│
 │◀──────────────────── ack(seq=2) ──────│  （可选）
 │      …… 状态变化（200 ms 防抖）或每 5 秒 ……
 │──── snapshot(seq=N) ─────────────────▶│
```

| 计时 | 值 | 说明 |
|---|---|---|
| 心跳 | 5 s | 主机至少每 5 秒发送一次 `snapshot` |
| 主机离线判定 | 15 s | 设备 15 秒内没有收到任何消息，应显示「主机离线」，保留最后的数据但置灰 |
| 握手重试 | 5 s | 主机在收到设备 `hello` 前每 5 秒重发 `hello` |
| 重新扫描 | 2 s | 串口断开或打不开时，主机每 2 秒重新查找设备 |
| 防抖 | 200 ms | 连续变化合并为一次发送 |
| 功能页 | 跟随 `snapshot` | `pages` 紧跟在 `snapshot` 后发送，见 §3.5 |
| 提示音 | 跟随 `snapshot` | 有任务开始等用户处理时，`beep` 跟在 `snapshot` 和 `pages` 后面，见 §3.6 |
| 红外 | 随时 | `ir_send` 在用户操作空调页时发送；`ir_recv` 在接收模块收到信号时发送 |

## 6. 兼容规则

1. 新增字段只能是可选字段；接收方忽略不认识的字段。
2. 新增消息类型不提升 `proto`；接收方忽略不认识的 `t`。
3. 删除字段、改变字段含义或类型、改变帧格式时，提升 `proto` 主版本。
4. 接收方遇到解析失败的行，丢弃该行并继续，不断开连接。
5. 固件升级用到的部分（§3.4、§4.5，以及 `hello` 的 `fw`、`ota` 字段）在任何 `proto` 版本里都保持不变，并且不受版本不兼容影响：协议版本不一致的设备正是靠它升级。

  亮的卡片只用暗底和细描边，不要大面积高亮，以免 AMOLED 烧屏。
- **数值加减卡片**（`stepper`，如温度）：不画图标；中间是 `text`（等宽粗体，一行时 52px，两行时 36px），左右各一个圆形按钮「−」「+」（一行时 72px，两行时 56px，底色 `#1C1C1E`，文字 `#F2F2F0`），`label` 在下面。`at_min` / `at_max` 时对应按钮 30% 不透明、不响应点击。
- **选项卡片**（`select`，如模式、风速）：和开关卡片一样排，图标和 `text` 用图标的颜色：`cool` `#5AA9FF`、`heat` `#FF9F43`、`dry` `#4FD1C5`、`auto` `#3DD68C`，其余 `#E9E9E5`；图标底 `#1C1C1E`。
- **图标**（`icon`，24 单位的网格，线宽 2，只用直线和圆弧，固件照着画；网页预览的 `SCR_ICONS` 是原样）：`bulb` 灯泡、`power` 电源（缺口圆 + 竖线）、`cool` 雪花、`heat` 太阳（圆 + 8 条光线）、`dry` 水滴、`fan` 风（三条带卷的横线）、`auto` 循环箭头。
- **点击**：点一下 `switch` 卡片发送 `action`（`act` 为 `toggle`），本地立刻显示「切换中」，直到下一条 `pages`；点 `select` 卡片发 `next`，点 `stepper` 的「−」「+」发 `dec` / `inc`，这两种不在本地改显示，等下一条 `pages`。屏幕变暗时第一下点击只用来唤醒，不发送；一次滑动不能同时算作点击。
- 当前页在新的 `pages` 里没有了，就回到 Agent 页。主机离线、固件升级的遮罩卡片对所有页面都一样。

### 7.2 时间计算

设备收到 `snapshot` 时记录 `base_now = now` 与 `base_ms = millis()`，之后：

```
当前时间 = base_now + (millis() - base_ms) / 1000
已持续   = 当前时间 - since
本轮时长 = turn_secs + (当前时间 - now)   （仅 running；需授权、等待输入时就是 turn_secs）
重置倒计时 = resets_at - 当前时间（≤0 时显示 `0m`）
```

这样两次 `snapshot` 之间界面的秒数也能平滑走动，不依赖板载 RTC。

### 7.3 其他

- **字库**：项目名、任务标题可能包含中文，需要内置 CJK 字库子集（例如 LVGL 字体转换器按常用 3500 字 + ASCII + 标点生成，16/20/24 px 各一套）。无法显示的字符用 `□` 代替，不要崩溃。
- **接收缓冲**：USB-Serial/JTAG 驱动的默认 RX 缓冲很小，请调到 ≥ 16 KB（`snapshot` 和 `pages` 会连着到达，各最多 4 KB），并在单独任务里持续读取；写串口使用非阻塞或带超时的写入。
- **板子版本**：ESP32-S3-Touch-AMOLED-2.41 有 V1 / V2 两个硬件版本，**引脚定义不同，示例程序不通用**。V2 板丝印有「Rev2.0」或外壳贴「V2」标签。写固件前先确认手上的版本。
- **建议框架**：V2 用 ESP-IDF 5.5.x + LVGL 9；V1 用 ESP-IDF ≥ 5.1.4 或 Arduino core ≥ 3.0.7 + LVGL 8.4。显示驱动 RM690B0（QSPI），触摸 FT6336（I2C）。
- **休眠**：深度/浅睡眠会让 USB 设备从主机上消失，主机会自动重连，但重连期间数据会中断。
