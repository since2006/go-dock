# 红外空调插件（格力）

## Context

灯光之后的第二个功能页：用屏幕板子外接的 38 kHz 红外发射模块控制格力空调，能调开关、温度、模式、风速；外接的红外接收模块用来听原装遥控器，让屏幕上的状态跟着变。红外是单向的，空调本身不回报状态。

## 决定

**1. 红外由屏幕板子发出，不走 MQTT。** 用户已有 38 kHz 发射和接收模块，接在 J8 排针上，不用再买网络红外转发器。

**2. 编码在电脑上，固件只收发原始波形**，做法和蜂鸣器一样：
- go-dock 把格力的 8 字节状态编码成 µs 时序，通过 `ir_send` 发给屏幕，屏幕用 RMT 按载波发出；
- 接收模块收到的波形用 `ir_recv` 原样传回，go-dock 解码；
- 以后加别的品牌、别的协议只改电脑端，不用改固件。

**3. 屏幕上用通用控件**，不为空调单独写页面：
- 新增两种 `kind`：`stepper`（数值加减）和 `select`（选项轮换）；
- 新增两个字段：`icon`（卡片图标）和 `at_min` / `at_max`（加减到头）。
- 以后的风扇、窗帘也能复用。

**4. 接收模块用来同步原装遥控器**，顺便识别遥控器用的格力协议型号（YAW1F / YBOFB）。

**5. 先做电脑端和网页预览**，固件等预览定稿、用户说「同步固件」再做（阶段 2）。在那之前，空调页显示「屏幕固件不支持红外」并置灰。

## 结构

```
网页「插件」/ 设备预览 / 屏幕点击 ─► plugins/aircon ──ir.GreeRaw──► device.Manager.SendIR ─ir_send─► 屏幕 RMT ─► 空调
                                         ▲                                              原装遥控器 ─► 接收模块
                                         └── ir.DecodeGree ◄── SetIRSink ◄── ir_recv ◄────────────────────┘
```

- **`internal/ir`**：格力编解码，对照 IRremoteESP8266 的 `ir_Gree.cpp`。
  - 时序：引导 9000 / 4500，位 mark 620，1 = 1600，0 = 540；4 字节 + 3 位块尾 `010` + 19980 µs 间隔 + 4 字节，共 139 个时长，载波 38 kHz。
  - 规则：温度 16–30；自动模式锁 25°C；除湿锁低风；YAW1F 型号开机时多置一位。
  - 校验：10 + 前 4 字节低 4 位 + 第 5–7 字节高 4 位，取低 4 位。
  - 遥控器设的摆风、灯光、睡眠等位原样保留，定时位不重发。
  - 测试用原库的真实遥控器状态做样例。
- **`device.Manager`**：
  - 能力协商同 `beep`：设备 hello 带 `"ir":1`；
  - `SendIR` 在屏幕不能发时立刻报错，不排队补发，残留超过 2 秒的帧直接丢弃；
  - `IRReady` 供页面判断能不能发；
  - `ir_recv` 交给 `SetIRSink` 注册的回调。
- **`plugins/aircon`**：
  - 四个控件：电源（switch）、温度（stepper）、模式（select）、风速（select）。
  - 开着时每次操作发一帧完整状态；关着时只记下来，开机一起发。
  - 收到遥控器的帧时更新状态；型号和设置不一致时提示一次。
  - 状态存在 `GO_DOCK_HOME/aircon.json`（0600），重启后恢复。
- **网页**：
  - 设备预览画三种卡片和七个图标，图标只用直线和圆弧，固件可以照着画；
  - 「插件」页加空调卡片：启用、名称、协议型号，以及实时状态和控制按钮。

协议细节见 `docs/protocol-v1.md` §3.5（控件）、§3.7（`ir_send`）、§4.6（`ir_recv`）、§7.1（卡片和图标）。

## 阶段 2：固件（已完成，待真机验证）

- **接线**（J8 排针，引脚已对照原理图）：

  | 模块 | 引脚 | 排针 |
  |---|---|---|
  | 发射模块 DAT | GPIO7 | 13 脚 |
  | 发射模块 VCC / GND | 3V3 / GND | 16 脚 / 18 脚 |
  | 接收模块 OUT | GPIO8 | 15 脚 |
  | 接收模块 VCC / GND | 3V3 / GND | 30 脚 / 33 脚 |

  发射模块如果带三极管、高电平触发，VCC 可以改接 31 脚（USB 5V），发射距离更远。
- **新增 `ir.c`**：
  - 发送：RMT TX 用 1 MHz 分辨率、38 kHz 载波、占空比 33%，空闲低电平；队列 4 帧。
  - 接收：RMT RX 接在 GPIO8 上，接收头输出低电平有效，要反相；信号最长 30 ms，过滤 1 µs 以下的毛刺；缓冲至少 512 个时长，开 DMA 或合并内存块。
  - 发送期间和发完后 50 ms 内收到的帧丢弃。
- **`link.c`**：
  - hello 加 `"ir":1`；
  - 解析 `ir_send`（校验长度和取值范围），交给 `ir.c`；
  - 收到的帧编码成 `ir_recv` 发回主机。
- **`model.h` / `link.c`**：控件加 `icon`、`at_min`、`at_max`，以及两种新 `kind`。
- **`ui.c`**：
  - 选项卡片：图标、文字按图标配色，点击发 `next`；
  - 加减卡片：`−` / `+` 两个可点的圆按钮，到头置灰；
  - 图标：照 `SCR_ICONS` 用 `lv_draw_line` / `lv_draw_arc` 画出 power、cool、heat、dry、fan、auto。
- **`sim.c`**：加空调页场景（30°C 时「+」置灰、自动模式温度置灰、除湿风速置灰）和七个图标的截图，检查点 −/+、模式、风速、电源发出的 `action`，以及到头和置灰的控件不响应。
- 实际做法：
  - 接收用全部 4 块 RX 内存（192 个符号，最多 384 个时长），没开 DMA；格力一帧 70 个符号，够用。
  - 图标做成线条和圆弧的表（`ICON_*`），由 `draw_icon` 画；`−`、`+` 也是画出来的，不依赖字体。
- **真机验证**：
  - 对着空调发一帧，确认能控制；
  - 按原装遥控器，看日志里解出的状态和型号；
  - 如果发不出去，先用手机摄像头看发射管亮不亮。

## 阶段 3：路线（未排期）

- **学习任意遥控器**：录下原始波形，原样重放，用在电视、风扇等；需要存储和管理按键，做成另一个插件。
- **更多空调品牌**：在 `internal/ir` 加编解码（美的、海尔、大金等），插件按配置选择品牌。
- **更多空调功能**：按需要再加摆风、睡眠、灯光、定时，可以做成 `select` 或 `switch`。
