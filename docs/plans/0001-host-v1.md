# go-dock v1 计划（host 端）

## Context

需求：在微雪 ESP32-S3-Touch-AMOLED-2.41-B（600×450 AMOLED，触摸）上显示 Claude Code / Codex 的套餐用量和任务状态（进行中、需授权、已完成），多个任务同时运行时也要能看清。采集端用 Go 写，支持 macOS / Windows / Linux，带网页管理台用于配置和看日志，网页通过 `go:embed` 打进同一个可执行文件。

现状：仓库为空（没有 commit），远端 `github.com/since2006/go-dock`，本机还没装 Go，也没装 Codex。v1 只实现 `host/`。`firmware/` 先放 README 占位，但 `docs/protocol-v1.md` 要定到能直接拿去写固件的程度。

已和用户确认：
- 用量 = 套餐额度 %（5h / 7d + 重置时间）+ 本地 token 统计
- 状态采集 = hooks（网页一键安装/卸载）为主，日志/状态文件兜底
- 屏幕布局 = 顶部两家额度，下方统一任务列表，按「需授权 > 进行中 > 刚完成」排序，每屏 4 条，滑动翻页
- 网页界面和文档用中文；代码、注释、标识符用英文

## 数据来源（调研结论）

**Claude Code**
- **实时状态（兜底，零配置）**：`~/.claude/sessions/<pid>.json`。字段有 `sessionId`、`cwd`、`status`（`busy|idle|waiting`）、`waitingFor`（如 `"permission prompt"`、`"input needed"`）和 `statusUpdatedAt`。这个文件未公开文档，要校验 PID 存活且 `procStart` 一致；文件消失或 PID 已死，就判定会话结束。
- **Hooks（主，文档化）**：写入 `~/.claude/settings.json`（遵守 `CLAUDE_CONFIG_DIR`），类型为 command：`"<exe>" hook claude --addr 127.0.0.1:47321`。
  - 事件：`SessionStart`、`UserPromptSubmit`、`PreToolUse`、`PostToolUse`、`PermissionRequest`、`Notification`、`Stop`、`StopFailure`、`SessionEnd`
  - 不用 `Notification(permission_prompt)` 做「需授权」信号，它要等约 6 秒才触发；改用 `PermissionRequest`，它是即时的。
  - hook 子命令永远静默并 `exit 0`，这样 daemon 没运行时 Claude 也不会报错。
- **套餐额度 %**：官方唯一来源是 statusLine 的 stdin 里的 `rate_limits.five_hour/seven_day.{used_percentage,resets_at}`。statusLine 只能配一个（用户现在用的是 claude-hud），所以 go-dock 安装成**包装器**：
  - `statusLine.command` 改成 `"<exe>" statusline --addr …`。原命令存进 go-dock 配置；包装器把 stdin 转发给 daemon（≤300ms，不阻塞），再用同样的 stdin 执行原命令并透传 stdout 和退出码。
  - 原命令的执行方式：Unix 用 `sh -c`；Windows 有 Git Bash 用 `bash -c`，否则用 `powershell -NoProfile -Command`。
  - 卸载时恢复原命令。**不读 OAuth 凭据，也不调非公开的 `/api/oauth/usage`**（claude-hud 已弃用这条路）。
- **Token 统计**：增量读取 `~/.claude/projects/**/*.jsonl`（含 `subagents/`）。
  - 按 `message.id` 去重，每个字段取最大值，按日、按模型累加 4 个 usage 字段。
  - 费用用内嵌价格表估算（API 等价价格）。实现时加载 claude-api skill 取当前价格，配置里允许覆盖。

**Codex**（本机未安装，靠 fixture 测试）
- **Hooks（主）**：写入 `$CODEX_HOME/hooks.json`（默认 `~/.codex`，JSON 结构与 Claude 相同，实现时按 learn.chatgpt.com/docs/hooks 核对 schema）。
  - 事件：`SessionStart`、`UserPromptSubmit`、`PreToolUse`、`PermissionRequest`（async）、`PostToolUse`、`Stop`、`Interrupt`、`SessionEnd`
  - **需要用户在 Codex 的 `/hooks` 里信任一次**，网页上要提示。
  - 不碰 `config.toml` 的 `notify`，避免改 TOML。
- **日志兜底**：轮询 `$CODEX_HOME/sessions/**/rollout-*.jsonl`（resume 会续写旧日期目录里的文件，所以要扫全树；跳过 `.jsonl.zst`）。
  - `task_started` → 进行中；`task_complete` → 已完成；`turn_aborted` → 已中断。
  - 有 `thread-writer-locks/<id>.lock` 表示会话打开（只检查存在，**绝不加锁**）。
  - 审批请求不落盘，所以无 hook 时识别不出「需授权」，这一点要在 UI 上写明。
  - `session_meta.history_mode` 的 legacy 和 paginated 两种都要兼容；`thread_source` 为 subagent/internal 的线程隐藏。
- **额度 %**：
  - 实时：最新的 `token_count.rate_limits` 中 `limit_id` 为 `codex` 或 null 的那条，取 `primary/secondary.{used_percent,window_minutes,resets_at}`，同时兼容旧字段 `resets_in_seconds` 和扁平的 `primary_used_percent`。
  - 补充：PATH 里有 `codex` 时，每 10 分钟启动一次 `codex app-server`（stdio JSON-RPC），依次发 `initialize`、`initialized`、`account/rateLimits/read`，然后退出。这条可在配置里关掉，失败不影响其他功能。
  - 不用 `wham/usage`，也不读 `auth.json`。
- **Token 统计**：对每个会话，`total_token_usage` 在相邻事件之间的差值记到事件所在日期。Codex 只显示 token，不算费用。

## 统一状态模型

`state` 枚举（优先级从高到低）：`approval` 需授权 > `input` 等待输入 > `error` 出错 > `running` 进行中 > `done` 已完成 > `idle` 空闲（默认不显示）。

- 每个会话：`id`（`provider:sessionId`）、`provider`、`project`（cwd 的 basename）、`state`、`detail`（如 `Bash: npm install`、标题或最后一句回复，截断到 48 个字符）、`since`、`updated`。
- 合并规则：hook 和状态文件各自产出 `Observation`，按会话合并，较新的覆盖较旧的。状态文件 / lock / PID 决定会话是否存活。
- `done` 超过 `done_ttl`（默认 30 分钟）后降为 `idle`。
- 列表排序：先按优先级，同级按 `updated` 倒序。最多 12 条（3 页）。

**事件映射**

| 来源 | 信号 | 映射到 |
|---|---|---|
| Claude hook | `UserPromptSubmit`、`PreToolUse`、`PostToolUse` | `running`，detail 写工具名 |
| Claude hook | `PermissionRequest` | `approval`，detail 写 `tool_name` 加命令摘要 |
| Claude hook | `Notification(elicitation_dialog)` | `input` |
| Claude hook | `Stop` | `done` |
| Claude hook | `StopFailure` | `error` |
| Claude hook | `SessionStart` | `idle` |
| Claude hook | `SessionEnd` | 移除会话 |
| Claude 状态文件 | `busy` | `running` |
| Claude 状态文件 | `waiting` + `"permission prompt"` / `"sandbox request"` | `approval` |
| Claude 状态文件 | `waiting` + 其他原因 | `input` |
| Claude 状态文件 | `idle`，且之前处于活动状态 | `done` |
| Codex hook | 同名事件，规则同上 | 同上；`Interrupt` → `idle`，detail 写「已中断」 |

## 协议 v1（`docs/protocol-v1.md`，摘要）

- **物理层**：板载 ESP32-S3 原生 USB（默认 VID:PID `303A:1001`，macOS `/dev/cu.usbmodem*`、Linux `/dev/ttyACM*`、Windows `COMx`）。打开串口时 DTR 开、RTS 关（RTS 会触发复位）。
- **帧格式**：UTF-8 换行分隔 JSON，每行 ≤4096 字节。无法解析的行（启动日志）忽略并按 debug 级别记录。
- **host → device**
  - 握手：`{"t":"hello","proto":1,"host":"go-dock","ver":"0.1.0"}`
  - `{"t":"snapshot","seq":N,"now":<unix>,"usage":{...},"sessions":[...],"counts":{...}}` 每次都发全量状态：状态变化时发（200ms 防抖），另外每 5 秒发一次当心跳。设备 15 秒没收到消息就显示「主机离线」。
  - `settings`（亮度、熄屏）在 v1 只预留，不实现。
- **device → host**
  - `{"t":"hello","proto":1,"fw":"…","w":600,"h":450,"max_line":4096}`
  - `{"t":"ack","seq":N}`
  - `{"t":"log","level":"…","msg":"…"}`，host 会把它转进网页日志
  - `touch` 预留
- **usage 结构**：`claude`/`codex` 各有 `five_hour`/`seven_day:{pct,resets_at}`、`today:{tokens,cost_usd?}`、`updated_at`。时间一律是 unix 秒，设备用 `now - x` 自己算倒计时和经过时长。
- 文档附 600×450 布局线框图（用户已选的布局），并说明固件需要 CJK 字库子集。

## 代码结构（`host/`，module `github.com/since2006/go-dock/host`，Go ≥1.25）

```
host/cmd/go-dock/main.go        子命令：run(默认) | hook <claude|codex> | statusline | version
host/internal/
  app/          组装与优雅退出（context 贯穿）
  config/       config.json，放在 os.UserConfigDir()/go-dock，含默认值与原子保存
  logx/         slog 扇出：文件（lumberjack 轮转）+ 内存环形缓冲（2000 条）+ SSE 订阅
  model/        Session/State/Usage/Snapshot/Observation
  hub/          合并、排序、TTL、发布订阅、构建快照
  ingest/       hook/statusline 子命令用的 POST 客户端（超时 1s，失败静默）
  procutil/     PID 存活检测（unix kill 0 / windows OpenProcess，x/sys）
  providers/
    jsonl/      通用增量 JSONL 读取（偏移、半行、截断检测）
    claude/     sessions.go hooks.go statusline.go transcripts.go install.go testdata/
    codex/      rollout.go locks.go hooks.go appserver.go install.go testdata/
    pricing/    内嵌价格表与费用计算
  device/       protocol.go manager.go（发现→打开→握手→写循环→重连）
                discover.go + discover_darwin_nocgo.go
  web/          server.go api.go sse.go middleware.go static/{index.html,app.js,app.css}
```

- **依赖**：`go.bug.st/serial` v1.8.0、`github.com/tidwall/gjson`、`github.com/tidwall/sjson`、`gopkg.in/natefinch/lumberjack.v2`。
- 文件变化用轮询检测，不用 fsnotify：sessions 目录 1 秒一次；近 48 小时内修改过的 jsonl 2 秒一次；全树扫描 30 秒一次。
- **串口与 cgo**：go.bug.st/serial 在 macOS 上做 VID/PID 枚举需要 cgo。所以 `discover.go` 用 enumerator 按 VID 303A 过滤；`darwin && !cgo` 构建改用端口名匹配 `usbmodem`。这样 CI 可以 `CGO_ENABLED=0` 交叉编译全部平台，本机开发照常用 cgo。
- **设备选择**：`device.port` 为 `auto` 或指定路径。auto 模式连第一个 303A 端口，在收到设备 hello 之前 UI 显示「未握手」（固件还没写）。拔掉后每 2 秒重扫一次。

**修改配置文件（install.go）**
- 用 gjson/sjson 只改 `hooks.<Event>` 和 `statusLine`，保留其他内容和格式。
- 写前备份成 `*.go-dock-<时间戳>.bak`，用临时文件加 rename 原子写入。
- 识别自家条目的方法：command 里含 go-dock 可执行文件名，且带 `hook claude` 或 `hook codex`。
- 重复安装是幂等的；可执行文件路径变了，UI 显示「路径失效，重新安装」。
- 实现时核对 Windows 下 command 的引号和 PowerShell 规则；优先用 Claude 文档里的 exec 形式。

## 网页管理台（127.0.0.1:47321，原生 HTML/JS，无构建步骤）

- **页面**
  - 概览：会话列表、两家额度、今日 token、设备连接状态
  - 设备预览：按 600×450 渲染与屏幕相同的布局，也是固件的视觉参考
  - 集成：Claude hooks、Claude statusline、Codex hooks 各自的状态和安装/卸载按钮，附说明
  - 设置
  - 日志：实时 SSE，可按级别过滤
- **API**
  - `GET /api/state`
  - `GET /api/events`（SSE：state 和 log）
  - `GET /api/logs`
  - `GET|POST /api/config`
  - `GET /api/integrations`、`POST /api/integrations/{name}/{install|uninstall}`
  - `GET /api/device/ports`、`POST /api/device/reconnect`
  - `POST /api/ingest/{claude|codex}/{hook|statusline}`：hook 响应必须是**空 body 的 200**，否则可能影响 Claude 的 PermissionRequest 决策
- **安全**
  - 只监听 127.0.0.1
  - 校验 Host 头，防 DNS rebinding
  - POST 必须是 `application/json`，防 CSRF
  - prompt 和工具参数只留在内存里；info 级别日志不记录 payload

## 实施顺序

1. 仓库骨架：文档、协议、AGENTS.md、CI、go.mod
2. config、logx、model、hub（含单测）
3. web 服务、嵌入页面、SSE、日志页、ingest 接口；`hook` 和 `statusline` 子命令
4. Claude provider：sessions 轮询、hook 映射、statusline 额度、transcript token、安装/卸载
5. Codex provider：rollout 读取、lock 检测、hook 映射、安装/卸载、app-server 轮询
6. device：协议、管理器、发现；设备预览页
7. 收尾：README、端到端验证

## 验证

- 环境：`brew install go`（≥1.25）。
- 单测：`cd host && go vet ./... && go test -race ./...`
  - hub 状态机：事件序列 → 状态、排序、TTL
  - Claude 和 Codex 的 fixture 解析，含 legacy/paginated 两种格式、旧版 rate_limits 字段
  - transcript 去重
  - install 的幂等性，且不破坏其他键（临时目录里放 settings.json 和 hooks.json）
  - 协议编码的 golden 文件与 4KB 上限
  - device manager 用 `net.Pipe` 模拟设备 hello、ack 和非 JSON 行
  - web 中间件：错误的 Host 返回 403，`text/plain` 返回 415
- 交叉编译：`CGO_ENABLED=0 GOOS={windows,linux,darwin} go build ./cmd/go-dock`
- 端到端（本机）：
  1. `go run ./cmd/go-dock` 并打开 http://127.0.0.1:47321。不安装任何集成，概览里就应该出现正在运行的 Claude Code 会话（来自 sessions 文件）。
  2. 在集成页安装 Claude hooks 和 statusline，检查 settings.json 的 diff 只涉及 hooks/statusLine，并且生成了 .bak。
  3. 在临时目录开一个新的 claude 会话，让它执行一个需要授权的 Bash 命令。概览和设备预览应立刻显示「需授权 Bash: …」，批准后变「进行中」，结束后变「已完成」。claude-hud 状态栏仍正常显示，第一次回复后出现 5h/7d 额度。
  4. 卸载后 settings.json 恢复原样。
- 串口（无硬件）：`socat -d -d pty,raw,echo=0 pty,raw,echo=0`，把 `device.port` 指向其中一端，`cat` 另一端，应能看到 NDJSON snapshot；往另一端写一行 hello，UI 应变为「已握手」。
- Codex：以 fixture 测试为准。如需实测，可 `npm i -g @openai/codex` 后重复第 3 步，并在 `/hooks` 中信任。
