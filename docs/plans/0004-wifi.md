# 屏幕走 WiFi

## Context

现在电脑只能用 USB 线连屏幕。目标：屏幕连上 WiFi 后监听一个端口，其他电脑上的 go-dock 通过局域网把用量、任务、CPU、内存等数据发过来，屏幕不必再和某一台电脑连线。

每台电脑照样跑 go-dock：读 `~/.claude`、Codex 记录、CPU 和内存的都是它，改的只是它和屏幕之间的连接。

## 决定

**1. 数据只走 WiFi，协议不变。** 屏幕监听 TCP **47322**，同样一行一条 JSON、一行不超过 4096 字节，`hello`、`snapshot`、`pages`、`action` 等照旧。只加可选字段和新消息，不升 `proto`。屏幕显示的一切都走这条连接，USB 不再传数据（后来简化的结果，最初设计里 USB 和 WiFi 二选一）。

**2. 不做 mDNS。** 在 go-dock 网页上手动填屏幕的 IP。路由器重启后 DHCP 可能换地址，所以配网时可以填固定 IP（或在路由器里绑定）。屏幕在「等待 go-dock」卡片上显示自己的地址和配对码。

**3. 配网经 USB。** 屏幕先用 USB 接一台电脑，在 go-dock 网页填 WiFi 名称、密码，可选固定 IP、掩码、网关，go-dock 通过 `wifi` 消息发给屏幕，屏幕存进 NVS。屏幕连上后用 `net` 消息报回地址和配对码，网页上一键填进设置。`wifi` 只在 USB 上有效，局域网里的人改不了屏幕的 WiFi。

**4. 配对码。** 屏幕第一次启动新固件时生成一个 6 位数字码，存在 NVS 里，之后不变。网络连接必须先发带正确 `code` 的 `hello`，否则屏幕回 `denied` 并断开，下一次连接要等 2 秒。没有配对码的话，局域网里谁都能连上来推假数据、发红外。

**5. 不加密。** 任务标题、消息、正在执行的命令以明文在局域网里传，文档里写明。

**6. USB 只用来设置 WiFi 和升级固件。** go-dock 有两条互不相干的连接：WiFi 上推数据；屏幕插着 USB 线时打开串口，只收发 `hello`、`wifi`、`wifi_scan`、`net`、`wifi_list` 和固件升级。没有「连接方式」选项。同一个 go-dock 断线重连时，靠 `hello` 里的主机 `id` 让新连接立刻接替旧连接。

**7. 网络连接上不升级固件。** 网络连接的 `hello` 不带 `ota`，固件升级仍走 USB（阶段 3 再放开）。

**8. 分两步做多台电脑。**
- 阶段 1：屏幕同一时间只服务一台电脑：先连上的那台占用屏幕，其他电脑收到「屏幕正被 xxx 使用」。
- 阶段 2：每台电脑独立一页（见下文），不做跨电脑合并。

## 结构

```
go-dock（任一台电脑）─┬─ 数据：TCP 拨号 屏幕IP:47322（device.addr、device.code）─┐
                      └─ 设置和升级：USB 串口（插着时）─────────────────────────┐ │
                                                                    ▼
                    屏幕 link.c：连接表（USB + 最多 4 条 TCP）── handle_line(conn) ── 解析、ui.c 照旧
                                 wlan.c：station、NVS 配置、配对码、状态
```

- 设备端每条连接一份状态：类型（USB / TCP）、是否已通过配对码、主机名、主机 id、最后收到消息的时间、行缓冲。
- 阶段 1 有一个「当前主机」（总是 WiFi 上的）：只有它的 `snapshot`、`pages`、`settings`、`beep`、`ir_send` 生效；屏幕的 `action`、`ir_recv`、`log` 只发给它。
- USB 上只处理 `hello`、固件升级、`wifi`、`wifi_scan`，任何时候都可以用 USB 升级。

## 阶段 1：配网 + 一台电脑走网络（已完成，待真机验证）

### 协议（`docs/protocol-v1.md`）

- §1 加「网络连接」：TCP 47322、配对、超时、明文。
- 主机 `hello` 加可选字段：
  - `name`：本机名称，最多 12 个字；
  - `id`：同一个 go-dock 不变的标识，`[a-z0-9]{1,16}`；
  - `code`：配对码，网络连接必填。
- 设备 `hello` 加 `"net":1`：能连 WiFi，接受 `wifi`。网络连接上不带 `ota`。
- 新消息：
  - `wifi`（主机 → 设备，只在 USB 上有效）：`{"t":"wifi","ssid":"…","pass":"…","ip":"…","mask":"…","gw":"…"}`。`ip` 为空时用 DHCP；`ssid` 为空时关掉 WiFi 并忘掉配置。
  - `wifi_scan` / `wifi_list`（只在 USB 上）：屏幕用自己的无线电扫描附近的 WiFi（只有它能连的 2.4 GHz 网络），网页列出来点选填入名称。
  - `net`（设备 → 主机，只在 USB 上发）：`{"t":"net","state":"connected","ssid":"…","ip":"…","port":47322,"code":"123456","fixed":true}`。`state` 取 `off` / `connecting` / `connected` / `failed`，`failed` 时附 `err`（中文原因）。握手后发一次，之后状态变化时再发。
  - `denied`（设备 → 主机，网络连接）：`{"t":"denied","msg":"配对码不对"}`。发完设备断开连接。
- §5 时序：
  - 网络连接 5 秒内没有发来正确的 `hello`，设备断开；
  - 连接 20 秒没有收到任何消息，两端都断开（主机每 5 秒一次心跳，设备每个 `snapshot` 都回 `ack`）；
  - 主机连不上时每 5 秒重试，收到 `denied` 后等 10 秒。
- §7.1：遮罩卡片的 WiFi 文案。

### 固件

- **`wlan.c` / `wlan.h`（新；不叫 `wifi.c`，免得和 ESP-IDF 的 `wifi_config_t` 等名字撞上）**：
  - station 模式；配置（SSID、密码、固定 IP、掩码、网关）存在 NVS 的 `wifi` 命名空间；
  - 断线后按 1、2、4…30 秒退避重连；
  - 状态和失败原因（密码不对、找不到这个 WiFi 等）供 `link.c` 发 `net`、供 `ui.c` 显示；
  - 配对码第一次启动时生成并保存；
  - 显示缓冲要在 WiFi 之前分到内部 RAM，所以在 `lvgl_task` 里 `display_init` 之后才启动 WiFi；
  - `sdkconfig.defaults` 打开 `CONFIG_SPIRAM_TRY_ALLOCATE_WIFI_LWIP`，关掉省电模式（屏幕本来就常亮，省电会让收包慢几百毫秒）。
- **`link.c`**：
  - 抽出连接表：USB 一条、TCP 最多 4 条；`send_line` 按连接发；`handle_line` 加锁，USB 和 TCP 两个任务都调它；
  - TCP 服务任务：`select` 同时处理监听和各连接，按行切分；处理配对、超时、`denied` 后延迟断开；
  - 「当前主机」：网络连接在没有当前主机、或当前主机 15 秒没消息、或 `id` 相同时接替；
  - 解析 `wifi`，回 `net`；WiFi 状态变化时向 USB 发 `net`，不等主机问（主机可能只收到了屏幕上电时的 `hello`，自己没发）。
- **`ui.c`**：遮罩卡片按 WiFi 状态显示（主机名不显示，阶段 2 再加）：

  | 情况 | 副标题 | 小字 |
  |---|---|---|
  | 没配 WiFi | 用 USB 连接电脑，在 go-dock 里设置屏幕 WiFi | — |
  | 正在连 WiFi | 正在连接 WiFi「home」… | 也可以用 USB 连接电脑 |
  | 已连上 | 在 go-dock 里填屏幕地址 192.168.1.50 | 配对码 123456 |
  | 连不上 | WiFi「home」连不上：密码不对 | 用 USB 连接电脑重新配网 |

  主机离线时副标题照旧，小字在 WiFi 已连上时改成地址和配对码。卡片图标：没设置 WiFi 时用 USB 图标，其余用 WiFi 图标。
- **`sim.c`**：加 `wlan_*`、`link_over_net` 的桩，以及等待（连接中 / 已连上 / 连不上）和离线（已连上 / 重连中）的截图。

### 电脑端

- **`config.DeviceConfig`**：
  - `addr`：屏幕地址，`IP` 或 `IP:端口`，端口默认 47322；
  - `code`：配对码；
  - `name`：本机名称，空则用系统主机名；
  - `port`：只用于 USB 线（设置 WiFi、升级固件）；
  - `validate`：地址和 6 位配对码要么都填、要么都不填（还没设置屏幕），名称不超过 12 个字。
- **主机 `id`**：由系统主机名和 `GO_DOCK_HOME` 算出，不写进配置。
- **`device.Manager`**：
  - 两条循环：`runNet` 拨号屏幕地址推数据（超时 3 秒，开 keepalive），`runUSB` 查找并打开串口做设置和升级；状态分 `Status`（WiFi）和 `Status.USB`；
  - `hello` 带上 `name`、`id`，网络连接还带 `code`；
  - 收到 `denied`：记成错误显示在网页上，10 秒后再连；
  - 网络连接 20 秒没收到设备消息就断开重连；
  - 收到 `net` 记进 `Status.Net`；
  - `ConfigureWiFi` 只在 USB 已握手、设备带 `net` 时发 `wifi`。
- **网页「设置 → 屏幕」**：
  - 屏幕地址、配对码、本机名称，以及 USB 串口（只用来设置 WiFi、升级固件）；
  - 「屏幕 WiFi」：USB 连着且固件支持时显示当前 WiFi 状态和地址，可以扫描、填 WiFi 名称、密码、固定 IP（可选）后发给屏幕；连上后有「使用这块屏幕」按钮，填好地址和配对码；
  - 没插 USB 时点「升级固件」提示插线。
- **`POST /api/device/wifi`**：`{ssid, pass, ip, mask, gw}`。密码只经过这一次，不写日志、不存配置。
- **测试**：
  - 配置校验；
  - 用本地 TCP 监听假装设备：握手带 `code`、`denied` 后等待、20 秒无消息重连、`net` 解析；
  - `wifi` 只在 USB 上、设备支持时发送。

### 真机验证

- 内部 RAM：打开 WiFi 后看启动日志和 `heap_caps_get_free_size(MALLOC_CAP_INTERNAL)`，固件升级的 SHA 校验仍要能分到内存；
- 配网：密码错误、SSID 不存在、DHCP、固定 IP 都试一遍，屏幕文案对得上；
- 断网恢复：关路由器、重启路由器，看屏幕和 go-dock 各自能否自动连回；
- 两台电脑都填了屏幕地址：后连的那台网页上显示「屏幕正被 xxx 使用」。

## 阶段 2：多台电脑，每台一页（未开始）

- 设备端每条连接各存一份 `snapshot` 和 `pages`（PSRAM，每台约 120 KB），最多 4 台；
- 左右滑动的页面顺序：各台电脑的 Agent 页在前，后面是各台的功能页。只有一台电脑时界面和现在一样，不显示主机名；
- Agent 页顶栏的页名换成主机名；性能页标题带主机名（主机端在网络连接时加）；
- 功能页的点击只发回它来自的那台电脑，红外接收发给所有连接；
- 「屏幕」页只显示第一台的；网络连接上 `settings` 只在用户修改时发，不在每次连接时发，免得几台来回覆盖；
- 别的电脑有任务等授权、等输入时，顶栏对应的页码点变成琥珀色；蜂鸣器各台照响；
- 自动变暗看所有电脑有没有活跃任务；时钟用任一台的时间；
- 某台 15 秒没消息，它的页显示「离线」；断开 10 分钟后去掉；
- `DOCK_MAX_PAGES` 加大，`maxPages` 在主机端保持每台 4 页；
- 网页「设备预览」只画本机的页；`app.js`、`ui.c`、§7.1 同步改；
- 屏幕上加一处能看到地址和配对码的地方，给后来加入的电脑用。

## 阶段 3：路线（未排期）

- 网络连接上升级固件（配对后才允许）；
- TLS 或其他加密；
- mDNS 自动发现；
- 不用 USB 的配网（屏幕开热点网页配网，或蓝牙配网）。
